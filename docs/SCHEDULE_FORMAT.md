# universal-schedule v1 — формат расписания и инструкция для ИИ

Этот документ — спецификация JSON-формата расписания приложения «Расписание»
(universal-schedule) **и пошаговая инструкция для ИИ-ассистентов**: как изучить
файл расписания, приложенный пользователем (PDF, скриншот, таблица, текст),
и собрать из него валидный JSON, который пользователь вставит в приложении
через «Другое → Конфигуратор расписания → Экспорт/импорт».

Формат определен в коде: `shared/src/commonMain/kotlin/com/jetbrains/kmpapp/data/model/SemesterConfig.kt`.

---

## 1. Общий вид JSON

Корень — объект `ScheduleExport`:

```json
{
  "format": "universal-schedule",
  "formatVersion": 1,
  "semester": { ...SemesterConfig... }
}
```

Приложение принимает и «голый» `SemesterConfig` без обёртки, но рекомендуемый
вариант — полная обёртка.

### SemesterConfig

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `university` | string | **да** | Учебное заведение (полное или общепринятое сокращение, например «МГТУ им. Баумана») |
| `group` | string | **да** | Группа (например «ИУ5-21Б») |
| `course` | int | **да** | Курс, ≥ 1 |
| `semesterNumber` | int | **да** | Номер семестра, 1–8 |
| `semesterTitle` | string | нет | Подпись семестра, например «Осень 2026». Пусто — приложение покажет номер |
| `startDate` | string (дата) | **да** | **Понедельник первой недели** в формате `YYYY-MM-DD` |
| `weeksCount` | int | **да** | Количество учебных недель, ≥ 1 (обычно 15–18) |
| `bells` | массив `LessonBells` | нет | Звонки. По умолчанию 7 пар 09:00–21:10 |
| `entries` | массив `ScheduleEntry` | нет | Недельный шаблон занятий (без него семестр пустой) |

### LessonBells (звонок)

| Поле | Тип | Описание |
|---|---|---|
| `number` | int | Номер пары, 1..N, без пропусков |
| `startTime` | string | `HH:MM` (24 часа) |
| `endTime` | string | `HH:MM`, строго позже `startTime` |

### ScheduleEntry (занятие недельного шаблона)

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | string | **да** | Уникальная строка в пределах файла (например `e1`, `e2`, …) |
| `dayOfWeek` | int | **да** | День недели по ISO: 1 = понедельник … 6 = суббота, 7 = воскресенье |
| `bellNumber` | int | **да** | Номер пары (ссылается на `bells[].number`) |
| `subject` | string | **да** | Название предмета (не пустое) |
| `lessonType` | string | нет | Одно из: `LECTURE` (лекция), `PRACTICE` (практика), `LAB` (лабораторная), `OTHER` (занятие, по умолчанию) |
| `teacher` | string | нет | Преподаватель (имя как в источнике) |
| `classroom` | string | нет | Аудитория (с корпусом, если есть: «Б-301») |
| `subgroup` | string | нет | Подгруппа / примечание («1 подгруппа», «по вариантам») |
| `parity` | string | нет | `ALL` (каждую неделю, по умолчанию), `ODD` (нечётные), `EVEN` (чётные) |
| `firstWeek` | int | нет | Первая неделя занятия, по умолчанию 1 |
| `lastWeek` | int | нет | Последняя неделя; `0` (по умолчанию) = до конца семестра |

Неделя занятия существует, если `firstWeek ≤ неделя ≤ lastWeek` (или до
`weeksCount` при `lastWeek = 0`) **и** чётность совпала: `ODD` — нечётные
номера недель (1, 3, 5…), `EVEN` — чётные (2, 4, 6…). Нумерация недель
всегда от `startDate` (первая неделя = неделя `startDate`).

В один слот (день + пара) можно положить несколько entries — например две
подгруппы разных преподавателей; приложение покажет их в одной карточке.

## 2. Инструкция ИИ: из файла пользователя — в JSON

### Шаг 0. Собери обязательные данные
Из шапки документа или от пользователя нужны: **вуз, группа, курс, номер
семестра, дата начала семестра (понедельник 1-й недели), количество недель**.
Чего не хватает — **спроси у пользователя**, не выдумывай. Особенно дату
начала: без неё нумерация недель и чётность поедут.

### Шаг 1. Определи звонки
Если в файле есть колонка времени — перенеси её в `bells` (время в `HH:MM`).
Если времени нет — оставь `bells` пустым массивом или не указывай поле
(приложение подставит дефолт 09:00–21:10, 7 пар) и **предупреди пользователя**,
что время стоит проверить в конфигураторе.

### Шаг 2. Разбери недельную сетку
Типичные структуры источников:
- **«Числитель / знаменатель»** (или «верхняя / нижняя неделя», «1/2 неделя») —
  две колонки/строки: это чётность. Числитель = нечётные недели → `parity: ODD`,
  знаменатель = чётные → `parity: EVEN`. **Обязательно уточни у пользователя,
  какая неделя (нечётная или чётная) будет первой** — от этого зависит mapping,
  если в файле недели не пронумерованы.
- **«каждую неделю»** / одна строка без деления → `parity: ALL`.
- **Диапазоны недель** («3–8 нед.», «с 5 недели», «до 12.10») → `firstWeek` /
  `lastWeek`. Пересчитывай даты в номера недель от `startDate`.
- **Подгруппы** («1 п/гр», «2 п/гр») → отдельные entries с `subgroup`, обычно
  тот же слот; если подгруппы чередуются по неделям — kombiniруй с `parity`
  или диапазоном недель.
- Дни недели → `dayOfWeek` (Пн=1 … Вс=7). Пустые дни не создавай.

### Шаг 3. Типы занятий
Сопоставляй метки источника: ЛК/лекция → `LECTURE`; ПР/практика/семинар →
`PRACTICE`; ЛР/лабораторная → `LAB`; остальное (консультации, зачёты,
экзамены, «сам. работа») → `OTHER`. Не изобретай новые значения.

### Шаг 4. Собери JSON и проверь его
- `id` уникальны; `dayOfWeek` 1–7; `bellNumber` существует в `bells`
  (или ≤ 7 при дефолтных звонках).
- Все строки времени — `HH:MM`, конец позже начала.
- `startDate` — обязательно **понедельник** (`YYYY-MM-DD`). Если пользователь
  назвал другую дату, сдвинь на понедельник этой недели и скажи об этом.
- `1 ≤ firstWeek ≤ weeksCount`; `lastWeek = 0` или `firstWeek ≤ lastWeek ≤ weeksCount`.
- Обязательные строковые поля (`university`, `group`, `subject`) не пустые.
- JSON без комментариев и trailing-запятых; кириллица как есть (UTF-8,
  без \u-экранирования).

### Шаг 5. Выдай результат
Отдай пользователю **только один JSON-блок** (обёртка `ScheduleExport`) и
краткую инструкцию: сохрани JSON в файл `.json` и в приложении открой
«Другое → Конфигуратор расписания → Данные → Выбрать файл (.json)»
(или «Скопировать JSON в буфер» → «Импорт → вставить»). Отдельно перечисли,
что ты не смог определить из файла (время звонков, чётность первой недели,
диапазоны недель) и что стоит проверить.

## 3. Пример

Вход: таблица вуза «МГТУ им. Баумана», группа ИУ5-21Б, 2 курс, 3 семестр,
осень 2026; семестр с 31.08.2026 (понедельник), 16 недель; звонки вуза;
по понедельникам — лекция «Матанализ» каждую неделю (ауд. Б-301, Иванов И.И.)
и лабораторная «Физика» по чётным неделям (2 подгруппа, Л-214);
по средам — практика «Английский» недели 1–8 (Петрова А.С.).

```json
{
  "format": "universal-schedule",
  "formatVersion": 1,
  "semester": {
    "university": "МГТУ им. Н.Э. Баумана",
    "group": "ИУ5-21Б",
    "course": 2,
    "semesterNumber": 3,
    "semesterTitle": "Осень 2026",
    "startDate": "2026-08-31",
    "weeksCount": 16,
    "bells": [
      { "number": 1, "startTime": "08:30", "endTime": "10:00" },
      { "number": 2, "startTime": "10:10", "endTime": "11:40" },
      { "number": 3, "startTime": "12:10", "endTime": "13:40" },
      { "number": 4, "startTime": "13:50", "endTime": "15:20" },
      { "number": 5, "startTime": "15:50", "endTime": "17:20" },
      { "number": 6, "startTime": "17:30", "endTime": "19:00" }
    ],
    "entries": [
      {
        "id": "e1",
        "dayOfWeek": 1,
        "bellNumber": 2,
        "subject": "Математический анализ",
        "lessonType": "LECTURE",
        "teacher": "Иванов И.И.",
        "classroom": "Б-301",
        "parity": "ALL"
      },
      {
        "id": "e2",
        "dayOfWeek": 1,
        "bellNumber": 4,
        "subject": "Физика",
        "lessonType": "LAB",
        "classroom": "Л-214",
        "subgroup": "2 подгруппа",
        "parity": "EVEN"
      },
      {
        "id": "e3",
        "dayOfWeek": 3,
        "bellNumber": 3,
        "subject": "Английский язык",
        "lessonType": "PRACTICE",
        "teacher": "Петрова А.С.",
        "parity": "ALL",
        "firstWeek": 1,
        "lastWeek": 8
      }
    ]
  }
}
```

## 4. Чего делать нельзя

- Не выдумывай `university`, `group`, `course`, `semesterNumber`, дату начала
  и число недель — это обязательные данные; чего нет — спроси.
- Не подменяй чётность: если не уверен, какая неделя первая (числитель или
  знаменатель), спроси; ошибка тихонько перевернёт весь семестр.
- Не используй значения `lessonType` вне списка и `dayOfWeek` вне 1–7.
- Не отдавай несколько JSON-блоков или JSON с комментариями — импорт строгий.
- Экзамены/зачёты вне недельной сетки форматом не поддерживаются (версия 1) —
  их можно добавить как `OTHER`-занятие на нужной неделе диапазоном
  `firstWeek = lastWeek`.
